## Install

```bash
dotnet add package Honker
```

The .NET package wraps `Microsoft.Data.Sqlite` and loads the Honker extension.

## Open

```csharp
using Honker;

using var db = Database.Open("app.db", new OpenOptions
{
    ExtensionPath = "./libhonker_ext.dylib",
    WatcherBackend = "shm",
});
```

## Queue

```csharp
var q = db.Queue("emails");
q.Enqueue(new { To = "alice@example.com" });

var job = q.ClaimOne("worker-1");
if (job is not null)
{
    job.Ack();
}
```

## Job details and typed payloads

Claimed jobs and read-only snapshots carry the
[twelve job fields](/guides/queues/#job-fields) in PascalCase (`RunAt`,
`WorkerId`, `ClaimExpiresAt`, `MaxAttempts`, `CreatedAt`, `ExpiresAt`).

Watch the queue-name property, which is spelled two ways: `Job` and
`JobSnapshot<T>` call it `QueueName`, while the untyped `JobRow` calls it
`Queue`.

`db.Queue<T>(name)` returns a `TypedQueue<T>`:

```csharp
sealed record EmailPayload(string Recipient);

var emails = db.Queue<EmailPayload>("emails");

long id = emails.Enqueue(new EmailPayload("alice@example.com"),
    new EnqueueOptions(Priority: 7));

Job<EmailPayload>? job = emails.ClaimOne("worker-1");
if (job is not null)
{
    Console.WriteLine($"{job.Payload!.Recipient} {job.Attempts}/{job.MaxAttempts}");
    job.Ack();
}

JobSnapshot<EmailPayload>? snapshot = emails.GetJob(id);
// snapshot.State is "pending" until claimed; WorkerId and ClaimExpiresAt are
// null until then. PayloadRaw holds the raw JSON text alongside Payload.
```

The typed path decodes for you on both sides. The untyped `Queue` gives you
`Job` (payload as a `JsonElement`, plus `GetPayload<T>()`) and `JobRow`
(payload as raw JSON text).

On a claimed job, `WorkerId` and `ClaimExpiresAt` are non-null — the
constructor throws if the core returns a claim without them. On a snapshot both
are nullable, along with `ExpiresAt`.

`TPayload` is a compile-time contract only. honker never validates payload
shape at runtime.

## Transactional Outbox

```csharp
var outbox = db.Outbox("email", async payload =>
{
    await SendEmail(payload);
});

using (var tx = db.BeginTransaction())
{
    tx.Execute("INSERT INTO orders (id, total) VALUES (@p0, @p1)", 42, 9900);
    outbox.Enqueue(new { OrderId = 42 }, transaction: tx);
    tx.Commit();
}

await outbox.RunWorker("email-worker");
```

## ORM Section

If your app uses `Microsoft.Data.Sqlite` directly, share the same
`SqliteConnection` and transaction. With EF Core, Honker does not ship an EF
provider; keep a small wrapper that executes Honker SQL through the same
connection/transaction EF is using, or move enqueue-critical writes into an
explicit SQLite transaction.

See the full [.NET ORM recipe](/guides/orm/dotnet/) for connection-sharing
examples.

## Testing

Use temporary files and subprocess queue workers for watcher backend tests.
That catches native extension loading, SHM reopen behavior, and wake delivery
across real .NET processes.
