## Install

```elixir
def deps do
  [
    {:honker, "~> 0.4"}
  ]
end
```

Elixir uses `exqlite` and the compiled Honker extension.

## Open

```elixir
{:ok, db} =
  Honker.open("app.db",
    extension_path: "./libhonker_ext.so",
    watcher_backend: "shm"
  )
```

## Queue

```elixir
{:ok, _id} = Honker.Queue.enqueue(db, "emails", %{to: "alice@example.com"})

case Honker.Queue.claim_one(db, "emails", "worker-1") do
  {:ok, job} -> Honker.Job.ack(db, job)
  {:ok, nil} -> :ok
end
```

## Job details and typed payloads

A claimed `%Honker.Job{}` and a `%Honker.JobSnapshot{}` from `get_job/2` both
carry the [twelve job fields](/guides/queues/#job-fields) under the core's
`snake_case` names.

Both are structs, so use dot access — not string-key map access:

```elixir
{:ok, id} = Honker.Queue.enqueue(db, "emails", %{"to" => "alice@example.com"}, priority: 7)

{:ok, job} = Honker.Queue.claim_one(db, "emails", "worker-1")
job.payload        # already decoded: %{"to" => "alice@example.com"}
job.state          # "processing"
job.attempts       # 1
{:ok, true} = Honker.Job.ack(db, job)
```

`get_job/2` returns a snapshot whose `payload` is the raw JSON text, unlike a
claimed job's decoded payload:

```elixir
{:ok, snap} = Honker.Queue.get_job(db, id)
snap.state                    # "pending" until claimed
snap.worker_id                # nil while pending
Jason.decode!(snap.payload)
```

On a claimed job, only `expires_at` is nullable. On a snapshot, `worker_id`,
`claim_expires_at`, and `expires_at` are all nullable.

Elixir has no typed payload surface. honker never validates payload shape at
runtime, so every producer on a queue has to agree on the shape by itself.

## Pub/Sub

```elixir
{:ok, subscription} = Honker.listen(db, "orders")
ref = subscription.ref

receive do
  {:honker_notification, ^ref, notification} ->
    IO.inspect(notification.payload)
end

Honker.unlisten(subscription)
```

Subscriptions are live-only and channel-filtered. They stop automatically
when the subscribing process exits, or explicitly through `Honker.unlisten/1`.

## Transactional Outbox

```elixir
outbox =
  Honker.outbox(db, "email", fn payload ->
    MyApp.Email.deliver(payload)
  end)

Honker.Transaction.transaction(db, fn tx ->
  Honker.Transaction.execute(tx, "INSERT INTO orders (id, total) VALUES (?, ?)", [42, 9900])
  Honker.Outbox.enqueue_tx(outbox, tx, %{order_id: 42})
end)

Honker.Outbox.run_once(outbox, "email-worker")
```

## ORM Section

For Ecto, load the Honker extension through the SQLite adapter/exqlite
connection setup. Keep business writes in `Ecto.Multi`, then add a step that
executes `honker_enqueue` or `notify` on the same transaction.

See the full [Elixir ORM recipe](/guides/orm/elixir/) for Ecto.Multi examples.

## Testing

Use `System.tmp_dir!()` plus a real `.db` file and start worker processes with
the same extension path. Avoid in-memory SQLite for anything that needs worker
or watcher fidelity.
