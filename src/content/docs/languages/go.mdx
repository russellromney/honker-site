## Install

```bash
go get github.com/russellromney/honker-go
```

The Go binding uses `mattn/go-sqlite3`, so applications also need the compiled
`libhonker_ext.{so,dylib,dll}` on disk.

## Open

```go
db, err := honker.OpenWithOptions("app.db", "./libhonker_ext.so", honker.OpenOptions{
    WatcherBackend: "shm",
})
if err != nil { log.Fatal(err) }
defer db.Close()
```

## Queue

```go
q := db.Queue("emails", honker.QueueOptions{})
_, _ = q.Enqueue(map[string]any{"to": "alice@example.com"}, honker.EnqueueOptions{})

job, _ := q.ClaimOne("worker-1")
if job != nil {
    _, _ = job.Ack()
}
```

## Job details and typed payloads

A claimed `Job` and a `JobRow` snapshot from `GetJob` both carry the
[twelve job fields](/guides/queues/#job-fields), renamed to Go's exported
casing (`RunAt`, `WorkerID`, `ClaimExpiresAt`, `MaxAttempts`, `CreatedAt`,
`ExpiresAt`).

Go has no typed queue handle. It has one generic helper, `DecodePayload[T]`,
which you call wherever you need the payload as your own type:

```go
type EmailPayload struct {
    Recipient string `json:"recipient"`
}

q := db.Queue("emails", honker.QueueOptions{})

id, err := q.Enqueue(EmailPayload{Recipient: "alice@example.com"}, honker.EnqueueOptions{})
if err != nil { return err }

job, err := q.ClaimOne("worker-1")
if err != nil { return err }
if job != nil {
    email, err := honker.DecodePayload[EmailPayload](job.Payload)
    if err != nil { return err }
    fmt.Println(email.Recipient, job.Attempts, "/", job.MaxAttempts)
    job.Ack()
}
```

`Job.Payload` is `[]byte`. The snapshot's `JobRow.Payload` is a `string`, with
`PayloadBytes()` to bridge:

```go
row, err := q.GetJob(id)
if err != nil { return err }
if row != nil {
    // row.WorkerID and row.ClaimExpiresAt are nil pointers while pending.
    email, err := honker.DecodePayload[EmailPayload](row.PayloadBytes())
    _ = email
}
```

On a claimed `Job`, `WorkerID` and `ClaimExpiresAt` are plain values — the
claim sets both. On a `JobRow` they are pointers, along with `ExpiresAt`, so
`nil` means the job has not been claimed.

`DecodePayload` is a compile-time convenience. honker never validates payload
shape at runtime.

## Transactional Outbox

```go
outbox := db.Outbox("email", func(ctx context.Context, payload json.RawMessage) error {
    return sendEmail(ctx, payload)
}, honker.OutboxOptions{})

tx, _ := db.Transaction(ctx)
_, _ = tx.Exec("INSERT INTO orders (id, total) VALUES (?, ?)", 42, 9900)
_, _ = outbox.EnqueueTx(tx, map[string]any{"order_id": 42}, honker.EnqueueOptions{})
_ = tx.Commit()

_ = outbox.RunWorker(ctx, "email-worker")
```

## ORM Section

For `database/sql`, use the Honker binding directly or register a sqlite3
driver variant that loads the extension on every connection. For GORM, feed
that driver name into GORM and run Honker SQL from inside `db.Transaction`.

See the full [Go ORM recipe](/guides/orm/go/) for driver registration and
accessing the raw `*sql.Tx` in GORM.

## Testing

Use `exec.Command` subprocess workers for watcher-backend proof tests. That
exercises extension loading per process, SQLite reopen behavior, and
cross-process wake delivery.
