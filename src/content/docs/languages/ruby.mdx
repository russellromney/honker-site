## Install

```bash
gem install honker
```

Ruby uses the `sqlite3` gem and a compiled `libhonker_ext.{so,dylib}`. The
sqlite3 build must expose `enable_load_extension`.

## Open

```ruby
require "honker"

db = Honker::Database.new(
  "app.db",
  extension_path: "./libhonker_ext.dylib",
  watcher_backend: "shm",
)
```

## Queue

```ruby
q = db.queue("emails")
q.enqueue({ to: "alice@example.com" })

job = q.claim_one("worker-1")
if job
  send_email(job.payload)
  job.ack
end
```

## Job details and typed payloads

A claimed `Job` and a `JobSnapshot` from `get_job` both carry the
[twelve job fields](/guides/queues/#job-fields) under the core's `snake_case`
names, with one exception: `Job#queue_name` holds the queue name, because
`@queue` is the queue object.

```ruby
q = db.queue("emails")
id = q.enqueue({to: "alice@example.com"}, priority: 7)

job = q.claim_one("worker-1")
if job
  job.payload          # already parsed: {"to" => "alice@example.com"}
  job.queue_name       # "emails"
  job.state            # "processing"
  job.attempts         # 1
  job.ack
end
```

`get_job` returns a `JobSnapshot` struct. Unlike a claimed job, its `payload`
is the raw JSON text — parse it yourself:

```ruby
snap = q.get_job(id)       # JobSnapshot, or nil
if snap
  snap.state               # "pending" until claimed
  snap.worker_id           # nil while pending
  JSON.parse(snap.payload)
end
```

The snapshot answers to both `#queue` and `#queue_name` for the queue name.

Ruby has no typed payload surface — payloads are whatever `JSON.parse`
produces. honker never validates payload shape at runtime, so every producer on
a queue has to agree on the shape by itself.

## Pub/Sub

```ruby
db.listen("orders") do |notification|
  puts notification.payload
end
```

`Database#listen` is live-only and channel-filtered. It returns an enumerable
listener when no block is given; call `listener.next(timeout_s: 5)` for a
bounded wait and `listener.close` when finished.

## Transactional Outbox

```ruby
outbox = db.outbox("email", ->(payload) { SendEmail.call(payload) })

db.transaction do |tx|
  tx.execute("INSERT INTO orders (id, total) VALUES (?, ?)", [42, 9900])
  outbox.enqueue({ order_id: 42 }, tx: tx)
end

outbox.run_worker("email-worker")
```

## ORM Section

For Rails and ActiveRecord, load the Honker extension on the ActiveRecord
SQLite connection, then call `honker_enqueue` or `notify` inside
`ActiveRecord::Base.transaction`.

See the full [Ruby ORM recipe](/guides/orm/ruby/) for Rails initialization and
a small wrapper module.

## Testing

Run queue and outbox worker proofs in subprocesses. In CI, require a sqlite3
gem build with loadable-extension support so watcher e2e coverage cannot
silently skip.
